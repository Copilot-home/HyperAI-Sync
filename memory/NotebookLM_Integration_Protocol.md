# NotebookLM Integration Protocol

## Role

NotebookLM is the system's semantic read model. It is optimized for source-grounded exploration, topic relationships, briefing, and mind maps. It is not a queue, scheduler, secret store, transaction log, or action authority.

## Modes

### Mode A — consumer NotebookLM with stable Google Docs

Recommended for the current local-rich environment. **Active now.**

- Keep six bounded source documents with stable identities.
- Import those documents into one NotebookLM notebook once.
- The hub recompiles local Markdown/JSON on every cycle.
- `hyperai_notebooklm_drive.py` updates the same Google Docs when `AX_NOTEBOOKLM_DRIVE_ENABLED=1`.
- NotebookLM refreshes from the Drive-backed sources.
- Avoids browser automation, repeated source creation, duplicated notebooks, and accidental cross-project context mixing.
- Mind Map is still generated by the user inside NotebookLM UI; data is already structured and ready.

### Mode B — Gemini Notebook Enterprise API

Use only when the account/project/license and preview API are intentionally configured. `hyperai_notebooklm_enterprise.py` is the scaffold.

- API: `https://us-discoveryengine.googleapis.com/v1alpha/projects/PROJECT_NUMBER/locations/us/notebooks`
- `discoveryengine.googleapis.com` enabled in project `antigravity-apo-4287`.
- **License required**: `SUBSCRIPTION_TIER_NOTEBOOK_LM_INTERACT` (or `SUBSCRIPTION_TIER_NOTEBOOK_LM`).
- Without license, the API returns `FAILED_PRECONDITION`.
- If a license is assigned, `hyperai_notebooklm_enterprise.py --create` can create a notebook and add the six Drive sources, after which Mind Map can be requested through the API.
- Set `AX_NOTEBOOKLM_ENTERPRISE_ENABLED=1` to activate.

### Mode C — consumer NotebookLM via `notebooklm-py` (unofficial, cookie-based)

**Executed now.**

- Installed `teng-lin/notebooklm-py` skill / CLI via `uv tool install "notebooklm-py[browser]"`.
- Authenticated by extracting cookies from Chrome profile (`notebooklm login --browser-cookies chrome --include-domains=all`).
- Created notebook `Σ_APΩ` at `https://notebooklm.google.com/notebook/cd7f0d8b-b727-4238-8664-196e0bf5f814`.
- Added all 6 Google Docs from the Drive manifest as sources (all `ready`).
- Generated an interactive mind map (`Hệ thống Sơ đồ`) and downloaded its JSON to `~/.axcanon/memory/notebooklm/notebooklm_mindmap_interactive.json`.
- This is the real "NotebookLM được gọi": HyperAI loads the skill, authenticates, and drives NotebookLM programmatically.
- **Caveats**: uses undocumented Google APIs; can break; rate limits apply; requires fresh Chrome cookies/session.
- Activation gate: have `notebooklm` on PATH and a valid `~/.notebooklm/profiles/default/storage_state.json`.

### Mode D — model-native local synthesis

**This is the actual mechanism to "call" NotebookLM.**

- HyperAI is an AIOS / model-native execution system (`AIOS_MODEL_NATIVE_RUNTIME_CANON.md`).
- NotebookLM, Google Cloud, and all external surfaces are `phi_i(M)` projections of the same model `M`.
- The `hyperai_notebooklm_compile.py` cycle now calls `hyperai_notebooklm_query.synthesize()` after each compile.
- `synthesize()` loads the 6 bounded source docs + `context_index.md` + `knowledge_graph.json`, sends them to a local Ollama model, and writes the structured output to `synthesis.md`.
- The model acts as the semantic read engine: it summarizes, builds a mind map, identifies topic relationships, and proposes follow-up questions.
- This is the bounded, source-grounded, local-first "NotebookLM call".
- Default model: `qwen2.5:1.5b`. Override with `AX_NOTEBOOKLM_SYNTH_MODEL`.
- Mode A (Drive) and Mode D (synthesis) are not mutually exclusive: Drive keeps Google Docs updated; the local model keeps `synthesis.md` fresh.

### Mode E — portable bundle

The fallback. Open or upload the compiled files manually. This mode works without Google credentials and is suitable for offline evidence review.

## Mind-map source structure

`knowledge_graph.json` organizes four planes:

- `knowledge`
- `execution`
- `connectors`
- `evidence`

`context_index.md` gives NotebookLM a causal spine:

```
Observe → Diagnose → Plan → Approval Gate → Execute → Verify → Record
```

The graph is data, not a second visual editor.
